1. Overview
--------------------------------------------------------------------
This script reads a list of astronomical images (typically JWST NIRCam/MIRI or HST
images) and produces a single *signal‑to‑noise ratio* (SNR) map.  The SNR map
is built by either

* summing the per‑pixel SNR values of each image, or
* **inverse‑variance weighting** the fluxes and propagating the combined variance
  (the default behaviour).

Optional features include:

* background subtraction before combination,
* rescaling the final SNR map so that the background RMS equals one,
* handling an *alternative* set of images that cover regions with poor
  multi‑wavelength coverage,
* masking of detected sources when estimating background statistics.

The script is meant to be run from the command line and is designed for
integration into a larger data‑reduction pipeline or for interactive use.

--------------------------------------------------------------------
2. Dependencies
--------------------------------------------------------------------
The script relies on the following third‑party Python packages:

* :mod:`numpy` – numerical array handling.
* :mod:`sep` – source extraction and background estimation (a Python wrapper
  around *SExtractor*).
* :mod:`astropy.io.fits` – reading and writing FITS files.
* :mod:`astropy.wcs` – handling World Coordinate System information.
* :mod:`argparse` – parsing command‑line arguments (part of the standard library).

If you are using the optional HST conversion routine ``jpui.HSTCountsTonJy``,
the :mod:`jpui` package (or a compatible implementation) must also be installed.

--------------------------------------------------------------------
3. Command‑line interface
--------------------------------------------------------------------
The script uses :func:`create_parser` to define a rich set of options.  The
most important arguments are reproduced below; all options are documented in
the help text generated by ``python snr_combination.py -h``.

.. code-block:: bash

   -i, --input_list INPUT_LIST
       Text file containing one FITS filename per line (default: ``input_list.txt``).

   -e, --err_list ERR_LIST
       Optional text file with a matching list of error images.  If omitted the
       error extensions are read from the science FITS files themselves.

   -bs, --background_subtract
       Perform a simple background subtraction on each image before combination.

   -o, --output OUTPUT
       Base name for the output FITS files (default: ``snr.fits``).  The script
       writes three files:
       ``OUTPUT``          – final SNR map,
       ``OUTPUT.signal``   – combined signal image (when ``--inverse-variance`` is used),
       ``OUTPUT.noise``    – combined noise image (same condition).

   --err-factor ERR_FACTOR
       Multiplicative factor applied to every error image (default: ``1.0``).

   -v, --verbose
       Print progress information.

   -iv, --inverse-variance
       Use inverse‑variance weighting (default: *enabled*).

   -rs, --rescale
       After the SNR map is built, rescale it so that the background RMS
       equals one.

   -a, --alt ALT
       Suffix for an *alternative* set of images (e.g. ``_alt``).  When given,
       the script creates a second SNR map that is merged into the primary
       one according to the masks supplied by ``--altmask`` and ``--altmasksw``.

   --mask MASK
       FITS image defining the region used to estimate the background SNR
       (default: ``mask.fits``).

   --altmask ALTMASK
       Mask image for the alternative coverage (default: ``f356w.fits``).

   --altmasksw ALTMASKSW
       Short‑wavelength mask for the alternative coverage (default:
       ``f277w.fits``).

4. Module‑level functions
--------------------------------------------------------------------
The script is organised into a handful of utility functions that encapsulate
specific tasks.  Each function is described below together with its inputs,
outputs and side‑effects.

--------------------------------------------------------------------
4.1 ``create_parser()``
--------------------------------------------------------------------
Creates and returns an :class:`argparse.ArgumentParser` instance pre‑populated
with all command‑line options described in section 3.  The function contains
no I/O and can be imported elsewhere for reuse.

--------------------------------------------------------------------
4.2 ``get_instrument(header_img)``
--------------------------------------------------------------------
**Purpose** – Identify the instrument that produced a given image.

*Parameters*  

* ``header_img`` – a FITS header (``astropy.io.fits.Header``).

*Returns*  

* ``flag_inst`` – a string: ``'HST'``, ``'NIRCAM'`` or ``'MIRI'``.  
  For HST the function checks the ``TELESCOP`` keyword; otherwise it falls back
  to the ``INSTRUME`` keyword.

*Side‑effects* – prints a diagnostic message when the instrument is HST.

--------------------------------------------------------------------
4.3 ``compute_flux_to_nJy(header_flux, flag_inst)``
--------------------------------------------------------------------
**Purpose** – Compute the conversion factor that turns the native flux units
in a FITS image into nano‑Janskys (nJy) and also retrieve pixel scale/WCS
information.

*Parameters*  

* ``header_flux`` – FITS header of the image to be converted.  
* ``flag_inst`` – instrument string returned by :func:`get_instrument`.

*Returns*  

* ``flux_to_nJy`` – multiplicative factor (float).  
* ``pixel_scale`` – size of one pixel in arcseconds (``sqrt(pixel_area)``).  
* ``wcs`` – an :class:`astropy.wcs.WCS` object constructed from the header.

*Implementation details*  

* For HST the routine attempts to use the ``PHOTFLAM`` and ``PHOTPLAM``
  keywords together with a helper ``jpui.HSTCountsTonJy``.  If those keywords
  are missing it falls back to the AB zero‑point stored in ``ZEROPNT``.
* For JWST (NIRCam/MIRI) the conversion is approximated as  

  ``1e15 / 4.25e10 * pixel_area``  

  which maps MJy sr⁻¹ → nJy assuming the standard JWST pixel‑area
  conversion factor (``4.25e10`` MJy sr⁻¹ = 1 Jy pixel⁻¹).

--------------------------------------------------------------------
4.4 ``detect_and_mask(data, mask=None)`` and ``iterative_detect_and_mask(data, niter=3)``
--------------------------------------------------------------------
Both functions wrap :mod:`sep` source detection.

* ``detect_and_mask``  

  *Inputs* – ``data`` (2‑D NumPy array), optional ``mask`` (boolean array).  
  *Process* –  

  1. Build a background model with ``sep.Background``.  
  2. Subtract the model from the data.  
  3. Detect objects using ``sep.extract`` with a detection threshold of
     ``1.5 sigma`` (the global RMS from the background model).  
  4. Expand each detection into an elliptical mask (radius ``r=3`` times the
     semi‑major axis) via ``sep.mask_ellipse``.  

  *Outputs* – a tuple ``(mask, objects)`` where ``mask`` is a boolean array
  with ``True`` for pixels belonging to detected sources and ``objects`` is the
  structured array returned by ``sep.extract`` (contains ``x, y, a, b, theta``).

* ``iterative_detect_and_mask``*  

  Calls ``detect_and_mask`` repeatedly (``niter`` times).  The first call
  produces an initial mask; subsequent calls refine the mask using the
  previous mask as input.  The final mask and the concatenated list of objects
  are returned.

These helpers are used by the background estimation functions below.

--------------------------------------------------------------------
4.5 ``background_level(data)`` and ``background_rms(data, flag_bs=False)``  
--------------------------------------------------------------------
* ``background_level`` – Returns the mean background of ``data`` after masking
  all detected sources (using the 3‑iteration routine).  The masked pixels are
  replaced by ``np.nan`` and the mean of the remaining pixels is computed.

* ``background_rms`` – Returns the standard deviation of the background.  When
  ``flag_bs`` is ``True`` the data are byte‑swapped first (this matches the
  behaviour required for some JWST products).  The routine also masks detected
  sources before computing ``np.nanstd``.

Both functions are useful for the optional *rescaling* step and for diagnostic
printing.

--------------------------------------------------------------------
4.6 ``main()``
--------------------------------------------------------------------
The heart of the script.  The flow can be summarised as follows:

1. **Parse arguments** – ``args = create_parser().parse_args()``.  
   Verbose output is printed if ``--verbose`` is set.

2. **Read input lists** – ``input_list`` (mandatory) and ``err_list`` (optional)
   are read into Python lists of file names.

3. **Iterate over the science images**  

   For each file ``i``:

   a. Open the FITS file with ``astropy.io.fits.open``.  
   b. Determine the instrument via :func:`get_instrument`.  
   c. Extract the image data and header.  For JWST the science data are in the
      second HDU (index 1); for HST they are in the primary HDU (index 0).  
   d. Convert the fluxes to nJy (and, for HST, back to MJy sr⁻¹) using
      :func:`compute_flux_to_nJy`.  
   e. Load the corresponding error image – either from the same FITS file or
      from a separate file supplied via ``--err_list``.  
   f. Multiply the error by ``args.err_factor``.  

   g. **Background subtraction** (optional) – ``background_level`` is called,
      its result subtracted from the science image.

   h. Build a boolean index ``idx`` that selects all *valid* pixels
      (finite data, finite error, non‑zero error and non‑zero data).

   i. **Combine**  

      *If ``--inverse-variance`` is set*  

      ```python
      snr[idx]      += data_image[idx] / data_err[idx]**2   # weighted flux sum
      snr_err[idx]  += 1.0 / data_err[idx]**2               # sum of inverse variances
      ```

      *Otherwise*  

      ```python
      snr[idx] += data_image[idx] / data_err[idx]           # simple SNR sum
      ```

   j. For the **last image** in the list the FITS header is saved as
      ``header_snr`` – this header will be written to the output files.

4. **Finalize the inverse‑variance combination** (executed only when
   ``args.iv`` is true)  

   * Compute the per‑pixel combined noise ``snr_err = (snr_err)**-0.5``.  
   * Derive the final SNR as ``snr / snr_err``.  
   * If ``--rescale`` is also requested, a second pass computes the RMS of the
     SNR in the region defined by ``--mask`` and rescales both signal and
     noise accordingly.  The rescaled signal/noise are saved with the suffixes
     ``.signal`` and ``.noise``; the final SNR image (still rescaled) is saved
     as ``args.output``.

5. **Alternative‑coverage handling** (triggered by ``--alt``)  

   The script repeats steps 2‑4 for a second set of input files whose names
   contain the suffix supplied via ``--alt``.  After the alternative SNR map
   ``snr_alt`` is built, a boolean mask is constructed from the three mask
   images (``args.altmask``, ``args.altmasksw`` and the primary ``args.mask``)
   to decide where the alternative values should replace the primary SNR
   values.

6. **Optional global rescaling** (if ``--rescale`` is set but ``--iv`` is *not*
   used) – the script recomputes the background RMS of the SNR image using
   ``background_rms`` and divides the entire image by that RMS.

7. **Write output** – The final SNR map is written to ``args.output`` (overwrites
   any existing file).  When inverse‑variance weighting is used, the separate
   signal and noise images are also written.

8. **Exit** – ``sys.exit(0)`` is implicit after the script finishes.

5. Detailed algorithmic notes
--------------------------------------------------------------------
* **Inverse‑variance weighting**  

  For a set of measurements :math:`F_i` with uncertainties :math:`\sigma_i`,
  the optimal combined flux is  

  .. math::
     F_{\mathrm{comb}} = \frac{\sum_i F_i / \sigma_i^{2}}{\sum_i 1/\sigma_i^{2}}

  and the combined uncertainty is  

  .. math::
     \sigma_{\mathrm{comb}} = \left(\sum_i 1/\sigma_i^{2}\right)^{-1/2}.

  The script implements exactly this formula by accumulating the numerator
  (`snr`) and denominator (`snr_err`) separately and performing the division
  after the loop.

* **Background estimation**  

  ``sep.Background`` builds a grid of background values and a global RMS.
  By masking detected sources (via ``detect_and_mask``) the script ensures that
  bright objects do not bias the background mean or variance.

* **Pixel‑scale handling**  

  The conversion from MJy sr⁻¹ to nJy depends on the pixel area on the sky.
  The script extracts the pixel area from the WCS by  

  ```python
  pixel_area = np.prod(wcs.pixel_scale_matrix.diagonal())
  ```

  and then uses ``sqrt(pixel_area)`` as the arc‑second scale.  This value is
  useful for users who need to know the physical size of a pixel.

* **Mask logic for the alternative coverage**  

  The masks are applied in the following order:

  1. Start with a *False* mask (no replacement).  
  2. Set ``True`` where the alternative SNR map has any non‑zero value.  
  3. Reset to ``False`` in regions where either ``altmask`` or ``altmasksw``
     indicate that the primary (long‑ or short‑wavelength) data already exist.  

  The resulting boolean array selects the pixels that should be overwritten
  with the alternative SNR values.

* **Byte‑swapping**  

  Some JWST products are stored in little‑endian format on disk but are read
  on big‑endian machines as signed integers.  ``background_rms`` offers a
  ``flag_bs`` switch that performs ``np.ndarray.byteswap().newbyteorder()`` to
  guarantee correct numerical values before background statistics are
  computed.

6. Example usage
--------------------------------------------------------------------
Assume you have three JWST NIRCam images (``f115w.fits``, ``f150w.fits``,
``f200w.fits``) and you want to generate an inverse‑variance weighted SNR map
with background subtraction and a final rescaling to unit background RMS.

1. Create a plain‑text list of the science files (one per line):

   .. code-block:: bash

      cat > input_list.txt << EOF
      f115w.fits
      f150w.fits
      f200w.fits
      EOF

2. Run the script:

   .. code-block:: bash

      python snr_combination.py \
          -i input_list.txt \
          -o combined_snr.fits \
          -bs \
          -rs \
          -v

   The command prints progress messages, subtracts a simple background from each
   image, combines them with inverse‑variance weighting, rescales the final SNR
   so that its background RMS equals one, and writes three FITS files:

   * ``combined_snr.fits``      – the rescaled SNR map,
   * ``combined_snr.fits.signal`` – the combined flux map,
   * ``combined_snr.fits.noise``  – the combined noise map.

3. If you have separate error FITS files, create ``err_list.txt`` with the
   matching paths and invoke the script with ``-e err_list.txt``.

7. Frequently asked questions
--------------------------------------------------------------------
**Q: Why does the script treat HST and JWST data differently?**  
A: HST images are usually stored in counts (electrons s⁻¹) while JWST
   NIRCam/MIRI calibrated images are in MJy sr⁻¹.  The conversion to a common
   unit (nJy) is required for proper weighting; HST also needs an extra step
   back to MJy sr⁻¹ after the conversion because the downstream pipeline expects
   that unit.

**Q: Can I change the detection threshold for source masking?**  
A: Yes.  The threshold is hard‑coded in ``detect_and_mask`` as ``1.5`` sigma.
   To modify it, edit the line  

   .. code-block:: python

      objects = sep.extract(data_sub - bkg, 1.5, err=bkg.globalrms)

   and replace ``1.5`` with the desired value.

**Q: My images have a different extension for the error array (e.g. EXTNAME='ERR').**  
A: The script looks for the error image in the second HDU (index 1) when
   ``--err_list`` is **not** supplied.  If your data store the error elsewhere,
   either provide an explicit ``--err_list`` or adapt the ``if args.err_list``  
   block to read the correct extension.

**Q: How does the rescaling work when I do *not* use inverse‑variance weighting?**  
A: After the simple SNR sum is computed, ``background_rms`` evaluates the RMS
   of the SNR in the region defined by ``--mask``.  The whole image is then
   divided by that RMS, forcing the background RMS to be unity.

8. Limitations & possible extensions
--------------------------------------------------------------------
* The HST conversion relies on the external ``jpui`` module; if that module is
  unavailable the script will raise an ``ImportError``.
* The background subtraction performed by ``background_level`` is a *single*
  scalar value (mean of the background).  For images with strong large‑scale
  gradients a more sophisticated background model (e.g. a mesh with
  ``sep.Background`` parameters) may be required.
* The mask handling for the alternative coverage currently contains a subtle
  bug – the statements  

  .. code-block:: python

     mask[idx] == True
     mask[idx] == False

  perform a comparison rather than an assignment.  The intended behaviour
  should be ``mask[idx] = True`` / ``mask[idx] = False``.  Users who rely on the
  ``--alt`` feature should patch these lines.
* The script writes the combined signal and noise images **only** when the
  inverse‑variance option is active.  If you need those products for a simple
  SNR sum you must modify the ``main`` function accordingly.
